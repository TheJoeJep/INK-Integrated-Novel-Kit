# /outline: matching the outline to how you write

> **Tier 3. Procedural.** This runs documented stages in order. Where I'm suggesting actual plot
> content for a point, I'll say so. That's raw material, not the check.

**Say this on invocation:** *Building the outline to match how you actually work. Architect and
gardener are a ratio, not a binary, and we're locating yours before setting the points.*

**Source:** [`craft/structure/try-fail-cycles.md`](../../craft/structure/try-fail-cycles.md)
(Points on the map) · [`craft/structure/structure-models.md`](../../craft/structure/structure-models.md)

## Stage 1: Locate the ratio

Architect and gardener aren't a binary, they're a dial, and this skill's whole job is finding
where it's set for *this* project rather than assuming.

**Say this plainly, because it's the thing that makes the exercise worth doing even for a
committed discovery writer:** heavy architects spend their planning time up front, before a word
of prose exists. Heavy gardeners spend the equivalent time later, in revision, once discovery
writing has told them what the story actually is. **Both spend the same total time.** Neither
gets hours back by picking one end over the other. The dial only decides *when* the time gets
spent, not how much.

Ask where this project sits before setting any points. Don't infer it from the author's general
temperament. A gardener on most projects can still want a tighter map for one with a hard plot
mechanism (a mystery, a heist) that punishes drift.

## Stage 2: Set the points

Robert Jordan's method, and the one most discovery writers actually use without naming it: the
outline is a handful of bullet points. Character starts here, big event, big event, big event,
ends here. Roughly six for a gardener-leaning project. **Discovery-write between them** and see
how long it takes to get from one to the next.

More points is the architect direction. It's the same method at higher density, not a different
one. A heavy architect's outline is points on the map with the gaps mostly filled in, not a
different tool.

## Stage 3: Discovery-write between the points

Between any two points, the actual scene-to-scene work is discovery writing (or drafting, per
`/write`). This skill doesn't do that work. What it can do is name the engine that should run in
the gap: yes-but / no-and, escalating each attempt, per
[`try-fail-cycles.md`](../../craft/structure/try-fail-cycles.md). If a gap between two points
feels aimless once drafting starts, that's usually a missing escalation, not a missing point.

## Stage 4: Let the points do foreshadowing work

**This is the reason to do the exercise even if the plan itself gets ignored:** knowing a big
moment is coming lets you plant for it pages or chapters early, in passing, before you'd otherwise
think to. Jordan's own outline had *a person pulls a sword that is not a sword from a stone that is
not a stone* sitting as one bullet point for eleven books before it paid off. The point didn't
need to be detailed. It needed to exist early enough to seed.

For each point, ask: is there anything sitting between here and the previous point that could
quietly gesture at this one arriving?

## Stage 5: The escape hatch

If a point turns out wrong once the prose reaches it, or the discovery-write between two points
found a better shape than either point predicted: **you can fix anything in post.** The points
are a map, not a contract. Revision can add foreshadowing retroactively once the real ending is
known, the same way it can move, merge, or drop a point that stopped fitting. Don't let a stale
point drag a chapter toward a shape it's outgrown.

---

## The warning built into the method

**Jordan pitched *The Wheel of Time* as three books.** The ending in that three-book outline is
the ending Sanderson eventually wrote. Fourteen books later. He didn't add material on top of the
plan; the plan's points were the right points the whole time. It just took fourteen books to
travel between them, because every gap kept generating its own yes-but/no-and escalations.

**The takeaway for this skill:** points on the map tell you the *shape* of the book. They do not
promise you the *length*. Set them, then let the discovery-writing tell you how far apart they
actually are. Don't force the gap closed to protect an estimate the points never made.

## Output format

```
── OUTLINE ── points on the map, [project / act]

  RATIO          leaning gardener. Tight point count, wide gaps to discover in

  POINTS
    1. [character] starts here. [State]
    2. big event. [The sighting]
    3. big event. [The wound found]
    4. big event. [The choice forced]
    5. ends here. [State]

  GAPS           1→2  discovery-write, no engine named yet
                 2→3  yes-but/no-and: each attempt to explain it away costs him more
                 3→4  discovery-write, escalation open

  FORESHADOW     point 4 could be seeded as early as point 1. [What, where]

── ESCAPE HATCH ──
   None of this is load-bearing. If the gap between 2 and 3 finds a better
   point than either end predicted, keep the better point.

── OPTIONS ── (mine, raw material)
   ...
```

## Rules

- **Ask where the ratio sits. Don't assume it from habit.** A gardener can still want a tighter
  map for one project
- **Both ends spend the same total time.** Don't frame heavier planning as more work, or lighter
  planning as less. Say so explicitly if the author frames it that way
- **Six points is a floor for a mapped project, not a target.** More points is still the same
  method at higher density
- **Foreshadowing is a bonus of setting points early, not a requirement of the exercise:** a
  point can exist with nothing seeded for it yet
- **The gap between points is discovery writing or drafting, not this skill's job:** name the
  engine to use there, don't fill it in
- **Say the escape hatch out loud whenever a point looks shaky.** Revision fixes points; this skill
  shouldn't manufacture false confidence in one to avoid saying so
- **Don't write points into `plot/` unasked:** that's `/write` in Structure Mode
